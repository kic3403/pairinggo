# 29. 날씨·계절 추천 — "오늘 같은 날엔" (2026-10-02)

사용자 요청: 날씨·계절에 따라 추천하는 술·음식이 달라지게. 비가 오면 막걸리+파전, 추워질수록 도수 높은 술. **사는 곳의 날씨**로.
사용자 결정: 페어링 카드 **순위는 그대로 두고, 날씨 추천은 칸을 따로** 둔다.

## 1. 원칙

- **상황은 근거가 아니다.** 어울림 점수 S·등급·신뢰도(docs/26)에는 날씨·계절을 넣지 않는다. 카드 순서는 어제와 오늘이 같다(공유 링크·검색 색인도 같다).
- 날씨 추천은 **따로 둔 칸** "오늘 같은 날엔"(`WeatherPick`)에서만. 홈·술 상세·음식 상세·오늘의 페어링에 같은 칸.
- 규칙은 **docs/28 실측이 뒷받침하는 것만** 넣는다. 추정 조합은 넣지 않는다(근거 확인·약함만).
- 정적으로 만든 화면(검색 색인)은 바뀌지 않는다 — 칸은 브라우저가 `/api/v1/situation`을 불러 그린다. 조합이 없으면 칸을 그리지 않는다.

## 2. 판정 규칙 (`packages/shared/src/situation.ts`)

| 상황 | 판정 | 술 | 음식 | 근거(docs/28) |
|---|---|---|---|---|
| 비 `rain` | 강수형태 1·2·5·6 | 탁주 | 전(분류) + 빈대떡 | 전 1.74배·막걸리 1.19배(같은 달 안 1.66·1.23배, 20달 중 19~20달) |
| 눈 `snow` | 강수형태 3·7 | 추움과 같음 | 전 + 국물(탕·전골·찌개·국밥·나베·샤브) | 비 규칙 + 추움 규칙 |
| 추움 `cold` | 기온 5℃ 미만(모르면 12~2월) | 25도 이상·증류주·브랜디·약주·청주 + 위스키·사케·와인 | 국물·회·구이 + 겨울 제철 | 전통소주 1.4배·와인 1.7배·약주 1.6배·국물 1.4배 |
| 선선 `cool` | 5~15℃(모르면 9~11월) | 약주·청주, 12~25도(탁주 제외), 와인·사케 | 구이 + 가을 제철 | 10월 약주 134·전통소주 110·구이 119 |
| 따뜻 `warm` | 15~25℃(모르면 3~5월) | 탁주, 13도 이하 과실주 | 전·무침 + 봄 제철 | 막걸리 5월 114(최고) |
| 더움 `hot` | 25℃ 이상(모르면 6~8월) | 13도 이하 과실주·허니와인·탁주·리큐르 | 면·회 + 여름 제철 | 냉면·물회 3.8배, 막걸리 최저 |

비·눈이 기온보다 먼저. 날씨를 모르면(지역 없음·조회 실패) 계절로 구간을 정한다(`fromWeather=false`). 5~25℃ 사이는 실측에서 검색 차이가 거의 없어 계절(가을·봄)로 나눴다.

조합 고르기(`situationPairs`): 근거 확인·약함 조합 가운데 **술과 음식이 둘 다 맞는 것** 먼저 → 음식만 → 술만. 같은 묶음 안에서는 **사는 곳의 술**(`drinks.region` 첫 낱말 = 시·도) → 근거 확인 → 어울림 점수. 같은 술·같은 음식은 한 번씩. 술 상세(`situationForDrink`)는 그 술의 근거 있는 조합 중 오늘 같은 날의 음식, 없으면 그 술이 오늘 같은 날의 술일 때만 가장 믿을 만한 조합, 둘 다 아니면 칸 없음. 음식 상세는 대칭(사는 곳 술 먼저).

2026-10-02 실측(충남 기준): 상황마다 홈 3개 모두 '둘 다 맞음'·충남 술. 술 상세 칸이 생기는 술 71(비)~151(추움)/558, 음식 63~84/143.

## 3. 사는 곳

1. 로그인 회원: 프로필 **사는 시·도**(`users.sido`, 긴 이름 → `sidoShort`). `/api/account/consent`가 `sido`를 함께 내려 `SavedProvider.user.sido`.
2. 없으면 기기의 **관심 지역**(`RegionProvider`, `pg_region`) → `sidoOfRegion`(수도권·서울 하위 = 서울, 충남/충북 = 충남, 전남/전북 = 전남).
3. 그것도 없으면 **서울**(`assumed`) — 칸에 "서울 기준 · 내 지역으로"(관심 지역 고르기).

**방침 개정**: 사는 시·도의 목적이 "묶은 통계"에서 "그 지역 날씨·계절에 맞는 추천"으로 늘어 방침 본문(수집 항목 표·통계 문단)에 적고 **`CONSENT_VERSION` 2026-10-02**(기존 회원 다음 로그인 때 재동의), 시행일 2026년 10월 2일. 날씨는 시·도 단위로만 조회하고 회원 정보는 바깥으로 보내지 않는다.

## 4. 날씨 받기

- 기상청 **초단기실황**(공공데이터포털 `VilageFcstInfoService_2.0/getUltraSrtNcst`, 승인 2026-10-02) — `packages/server/src/weather.ts fetchNowcast(nx, ny)`: T1H 기온·PTY 강수형태·RN1 강수량. 정시 자료가 10분쯤 뒤에 올라오므로 10분 전이면 한 시간 앞, NO_DATA면 한 시간 더 앞.
- 격자 `shared WEATHER_GRID` 16곳(시·도 대표 지점 — 도는 도청 소재지·중심 도시 한 점).
- 캐시 `weather_now`(0052, 시·도 기본키): `apps/web/lib/weather.ts weatherFor(sido)` — 60분 안이면 그대로, 오래됐으면 받아 덮어씀, 실패하면 3시간 안 옛 값(그것도 없으면 null → 계절만), 실패 뒤 10분은 다시 묻지 않음, 프로세스 메모 5분, 같은 시·도 동시 요청은 한 번. **크론 없음** — 손님이 보는 시·도만 받는다(최대 16 × 하루 24번).
- 환경변수 **`DATA_GO_KR_KEY`**(공공데이터포털 일반 인증키 디코딩 값) — `apps/web/.env.local`과 **Vercel에 추가해야** 운영에서 날씨가 붙는다. 없으면 오류 기록 뒤 계절만으로 동작한다(화면은 비지 않음).

## 5. API·화면

- `GET /api/v1/situation?sido=&region=&d=&f=&n=` → `{ situation: { key, headline, why, icon, title, temp, precip, fromWeather, sido, assumed, at }, items[], self? }`. 공개 캐시 5분(주소마다).
- `WeatherPick`(`_components/WeatherPick.tsx`, 클라이언트): `mode=home`(조합 n개, 술 주황 × 음식 남색 → 음식 화면 `?d=`), `drink`(음식 칩 → 음식 화면 `?d=`), `food`(술 칩). 아래 줄에 근거 문장 + "서울 기준/충남 날씨 · 기상청 15시 관측". 클릭 이벤트 `situation_click`(key·mode·d·f·weather·sido).
- 자리: 홈 `HomeTabs` 아래(배너 위) · 술/음식 상세 '준비 중'·가까운 술 칸 아래, 페어링 카드 위 · `/today` 영웅 카드 아래(n=2).
- CSS `.box.wx`(상황별 왼쪽 띠 색·옅은 바탕), `.wx-pair`, `.wx-chips`, `.linkish`.

## 6. 안 한 것·다음

- 푸시 알림("오늘 비 와요 — 막걸리에 전")은 보류 — 날씨 푸시는 하루 한 번 아침 크론으로, 알림 켠 회원의 시·도별 날씨를 보고(`activityPush` 구조) 보낼 수 있다.
- 지역별 세분(시·군)은 안 한다 — 격자 16점이면 충분(검색 데이터도 전국 단위).
- 상세 화면 카드 순위에는 **끝까지 넣지 않는다**(사용자 결정).
- 규칙 수치는 docs/28 §날씨 대조를 기준으로 하고, 해마다 `season-trends --weather`를 다시 돌려 확인한다.
