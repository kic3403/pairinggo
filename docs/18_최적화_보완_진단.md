## 1. 페어링 추천 엔진 — 고칠 것 (우선순위 순)

### 1-1. 맛 분석 조합이 근거 조합 위에 오른다 (결함) — **완료 2026-09-13**
- 적용: ① 1,841조합(공개 1,790 + 검수 중 51) 전부 `profileFit`으로 다시 계산해 백분위 0~100(`calibrateFits`)으로 저장(`pnpm --filter @pairinggo/db pf-recalc`, 1,825건 값 변경) ② 근거 링크 있는 조합에 +3(`EVIDENCE_BONUS`) ③ 순위 = 등급 → 근거 링크 → 점수. 테스트: "어떤 음식 화면에서도 맛 분석이 같은 등급의 근거 조합 위에 오지 않는다"(이전 28/81 → 0).
- 결과: 근거 조합 485건 중 '시도해 볼 만'은 113건(이전 대부분), 맛 분석 1,305건 중 찰떡 0. 육회 상위 8이 모두 근거 조합(이전 8위가 맛 분석 낯꽃). 맛 프로필 백분위는 동점 덩어리가 커서(중앙값 61) 15% 항목의 변별력은 낮다 — 맛 궁합 규칙이 16종뿐이라 그렇고, 규칙을 늘리면 다시 돌리면 된다.

- 원인 ① 맛 프로필 점수 눈금이 둘: 기존 918조합의 `pf.s`는 술마다 늘린 값(맛 분석 중앙값 68, 근거 조합 중앙값 57), 신규 872조합은 `profileFit`(40 + 20×이유 수) 값(중앙값 80, 상위 25%가 100). 종합 점수의 15%가 이 값이라 신규 맛 분석이 +5 정도 이득을 본다.
- 원인 ② 점수 자체가 "근거 있음"을 크게 치지 않는다 — 블로그 근거(es 84~86, 보너스 +0.5)와 맛 분석(es 84~87, 보너스 0)이 사실상 같은 자리.
- 실측: 81개 음식(카드 8장 이상) 중 28곳에서 근거 없는 조합이 상위 8에 들고 근거 조합이 아래로 밀렸다. 육회 8위 소곡화주 낯꽃(맛 분석 47)이 예.
- 제안:
  1. **맛 프로필 점수를 한 눈금으로 다시 계산** — 1,790조합 전부 `profileFit`으로 계산한 뒤 백분위로 0~100 재배치(기존 `pf.plus/minus` 문구는 60% 이상 일치하므로 이유 표시는 유지). 같은 조합이 어느 화면에서든 같은 값.
  2. **근거 우선 정렬** — 종합 점수에 "근거 링크 있음 +3"을 넣거나, 같은 등급 안에서는 근거 조합을 먼저. 등급 경계는 그대로.
  3. 테스트로 고정: "근거 있는 조합이 같은 등급의 맛 분석보다 항상 앞" + "28/81 → 0".

### 1-2. '시도해 볼 만' 67% — 화면이 밋밋해진다
- 신규 술은 근거가 없으니 당연한 결과. 등급 경계를 낮추면 신뢰가 깨지므로 **경계는 두고 화면을 바꾼다**: 음식 상세는 근거 조합을 먼저 12장만 펼치고 나머지는 "맛 분석 N개 더 보기"로 접기(치즈플래터 98장 → 초기 12장, HTML 1/5). 술 상세는 8장이라 그대로.
- 홈·검색·핫한 페어링은 이미 등급·근거 순이라 영향 없음(확인).

### 1-3. 대중 언급 수 눈금
- `BLOG_REF`는 전체 95퍼센타일(8,976건)의 로그. 10만 건 넘는 조합 7건(화요·예담처럼 일반어와 겹치는 이름)이 25점 만점을 독차지하고, 0건 48조합은 0점. 중앙값 61건.
- 제안: 상한을 99퍼센타일로 자르고, 이름이 일반어와 겹치는 술(`generic`·QUERY_OVERRIDE 대상)은 언급 수 대신 술 중앙값으로 대체. 신규 술 중 "국순당 쌀막걸리·장수 생막걸리·옛날 생동동주"처럼 흔한 이름은 `generic` 표시가 필요(§2-3과 같은 목록).

### 1-4. 먹어봤어요 → 점수 반영 (데이터가 쌓인 뒤)
- 지금은 의도적으로 분리. 조합당 평가 10명 이상이면 윌슨 하한을 4번째 항목(예: 10%)으로 넣는 규칙을 미리 정해 두고, 그 전까지는 "N명 중 M명 어울렸다" 문구만. 현재 4건.

### 1-5. 상황 검색(intentSearch)
- 217종에서도 0.3ms. 다만 조건 칩이 맛 프로필 기반이라 1-1의 눈금 통일이 끝나야 신규 술이 공정하게 섞인다. 통일 후 "매운 안주·기름진 안주·가벼운 술" 세 검색의 상위 10을 눈으로 검수.

## 2. 데이터 보완

### 2-1. 근거 수집 (가장 큰 구멍)

- 후보 큐 draft 11,463건 — 사람이 다 읽을 수 없다. §5-3 방식(인용문에 술·음식 이름과 페어링 단서 단어가 모두 있는 것만)으로 먼저 거르면 1/10 이하. 이 필터를 어드민 검수 화면 기본값으로.

## 3. 성능·구조

- 페이지: 홈 0.07s · 목록 0.25s · 술 상세 0.11s · 음식 상세(치즈플래터) 0.27s/319KB · 검색 0.14s. 서버 계산은 병목이 아니다. 음식 상세 HTML 크기만 2-1-2 접기로 줄이면 됨.

- 발행 → 화면 반영까지 최대 15분(카탈로그 캐시 5분 + ISR 10분). 어드민 발행 직후 `revalidatePath`를 부르면 즉시.
