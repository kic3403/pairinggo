# 26. 페어링 추천 시스템 최적화 — 현황·데이터·계획 (2026-09-26)

사용자 요청: "지금 가져오는 데이터는 무엇이고, 더 가져올 수 있는 데이터는 무엇이며, 허수를 줄이고 근거를 100%에 가깝게 명확히 하려면 추천 시스템을 어떻게 최적화할지 먼저 정리". 운영 DB 실측(2026-09-26)과 점수 코드(`shared/pairing/score.ts`·`affinity.ts`) 기준.

## 3. 추천 시스템 최적화 계획

### 3-1. 원칙 — "어울림 점수"와 "근거 신뢰도"를 분리한다
지금은 한 숫자(0~100)에 근거 등급·동시 등장 수·추정을 섞어 등급을 매긴다. 바꾸면:
- **근거 신뢰도 C**(확인됨/약함/추정 3단계): 독립 출처 수와 등급으로만. 출처가 검증(링크 살아 있음 + 인용문이 본문에 존재)된 것만 센다. **추정(맛 분석)은 C=추정 → 절대 "찰떡"이 못 된다.**
- **어울림 점수 S**: 같은 C 안에서 순서를 정하는 값 — 근거 강도 + 대중 lift + 회원 평가 + 친화도.
- 카드에는 항상 **C를 먼저**("양조장 공식 · 출처 2개 · 2026.09 확인" / "추정 — 맛 분석") 보여 준다. 근거를 100%에 가깝게 명확히 한다는 것은 점수를 올리는 게 아니라 **모든 카드가 자기 근거를 그대로 보여 주고, 근거 없는 카드는 스스로 추정이라고 말하는 것**이다.

### 3-2. 점수식 교체
| 성분 | 지금 | 바꿈 |
|---|---|---|
| 전문가 점수 es(60%) | 등급 상수 | **폐지.** 사람(소믈리에 패널·양조장)이 실제로 매긴 값이 있을 때만 `expert_score`를 쓰고, 없으면 null |
| 출처 등급 보너스 | +0.5~4 | **근거 강도 E** = Σ 출처별 가중(official 1.0 · sommelier 1.0 · media 0.6 · blog 0.3 · user 0.3) × 검증 여부 × **독립성**(같은 도메인·같은 글은 하나로) → 포화 함수(1 − e^−E). 동일 조합에 출처 3개가 모이면 두 배가 아니라 "확인됨" |
| 대중 언급(25%) | 동시 등장 총수 | **lift** = count("술 음식") ÷ (count("술") × count("음식") ÷ 전체) — 흔한 이름의 부풀림이 사라진다. 술 이름 총수 1만~100만 밖이면 무효, 음식 이름도 같은 규칙. 상한·로그. 몫은 10%로 |
| 맛 분석(15%) | 친화도 AUC 0.60 | **동률 정렬용**과 설명 문구로만(5%). 근거가 2,000건을 넘으면 술 종류×음식 외에 술 개체×음식 분류를 더한 모델로 재학습 |
| 회원 평가 | 표시만 | **Wilson 하한**(5명 이상)으로 S에 15%. "별로"가 우세하면 C를 한 단계 내린다 |
| 등급 | 점수 60/40 | **찰떡 = C 확인됨 + S 상위** · 잘 어울림 = C 확인됨/약함 · 시도해 볼 만 = 추정. 추정 조합은 술당 8개·음식당 20개까지만 화면에(나머지는 "더 보기") |

### 3-3. 허수 제거 절차 (한 번 돌리고 크론으로 유지)
1. **출처 표 채우기** — 도메인→등급·독립성 규칙을 `sources`에 넣고 730건을 재분류: 더술닷컴 "양조장 등록 추천 음식" = official, 더술닷컴 제품 설명 = official(양조장 등록) 단 같은 페이지는 하나, 술담화·키햐 상품 페이지 = **판매처 큐레이션(새 등급 retail, 가중 0.5)**, 언론 = media, 개인 블로그·카페 = blog.
2. **근거 검증 크론**(주 1회, check-links 확장): 링크 200 + 인용문(띄어쓰기 무시) 본문 포함 → `verified_at`; 죽은 링크는 가중 0(카드에서 "출처 확인 불가" 표시), 4주 연속이면 등급 강등.
3. **대중 언급 재계산**: 술 이름 총수·음식 이름 총수를 함께 저장(`blog-counts`에 두 칸 추가)해 lift로 환산. 신선막걸리류 상위 80건이 먼저 내려간다.
4. **추정 조합 정리**: 음식당 상한(20)·술당 상한(8) 밖의 추정 조합은 `status: hidden`(삭제 아님). 치즈플래터 376 → 20.
5. **후보 11,584 AI 선별**(D5) → 승인분만 근거로. 승격은 인용문 있는 것만 허용.
6. **중복·상충 근거**: 같은 조합에 "별로"류 문장(예: "안 어울린다")은 음성 근거로 저장해 E에서 뺀다(지금은 없음).

### 3-4. 측정 — 바꿀 때마다 같은 자로 잰다
- **오프라인**: 근거 조합 vs 뒤섞은 조합 AUC(`fit-eval.ts`, 지금 0.60), 공식 조합을 상위 5에 올리는 비율(precision@5), 등급별 조합 수 분포.
- **사람 감사**: 매달 카드 50장 무작위 — 근거 링크를 열어 "정말 그렇게 말하나" 확인, 목표 정확도 95%.
- **온라인**: 카드를 본 뒤 저장·구매 링크·식당 링크 클릭률(events), 먹어봤어요 "어울렸다" 비율, 회원 평가와 등급의 일치율.
- 목표(3개월): 근거 있는 조합 12% → **40%**, 출처 2개 이상 조합 107 → 500, 추정 조합 화면 노출 4,374 → 1,500 이하, 감사 정확도 95%.

### 3-5. 순서
1. (1주) 3-1·3-2 점수식 + 카드의 신뢰도 표시 — 데이터가 늘기 전에 "추정"이 찰떡으로 보이는 문제부터. 테스트로 AUC·분포 고정.
2. (1주) 3-3 ①②③④ 허수 제거 스크립트·크론.
3. (2주) D5 후보 AI 선별 + D2 공식 홈페이지 근거 추출(인용 검증).
4. (병행) D1 파트너 입력 독려, D4 소믈리에 패널 섭외, D6 회원 평가 5명 이상부터 반영.
5. (근거 2,000건 뒤) 친화도 재학습, 회원 행동 신호 반영.
