# 03. 제품 요구사항 (PRD)

앱은 세 개다. ① 소비자 미니앱(앱인토스) ② 파트너 어드민(양조장·식당·바틀샵, 웹) ③ 운영 어드민(내부, 웹).
기능 우선순위: **P0** = 해당 Stage 출시 필수 · **P1** = 출시 후 2주 내 · **P2** = 다음 Stage.

### 1-3. 핵심 플로우

**A. 검색 → 추천 → 구매 (Stage 2)**
1. "육회" 검색 → 어울리는 술 TOP5 (근거 배지) → 1위 술 카드 "구매" 탭
2. 상품 상세: 판매자 = ○○양조장 (통신판매 승인 표시), 가격, 배송
3. 성인인증 미완료 → S14 (토스 인증) → 완료 시 복귀
4. 주문서 → 토스페이 → 결제 완료 → 주문 상세 + 푸시
5. 양조장 어드민에 주문 도착 → 송장 입력 → 소비자 푸시 → 배송완료 → 리뷰 요청

**B. 검색 → 추천 → 식당 예약 (Stage 3)**
1. "한산소곡주" 검색 → 어울리는 음식 TOP5 → 1위 "육회" 카드 "내 주변 식당"
2. 예약 가능 필터 → 식당 상세 (이 집의 페어링: 육회 × 한산소곡주 취급 표시)
3. 예약하기: 날짜·시간·인원 → 요청 → 매장 알림톡/어드민 → 승인 → 확정 푸시
4. 방문 전날 리마인드 → 방문 → 매장 '방문완료' 처리 → 리뷰·페어링 기록 요청

**C. 미등록 검색어 (Stage 4, AI 폴백)**
검색어 정규화 → DB 미스 → 캐시 조회 → Claude API 생성(JSON 스키마 검증) → 캐시 저장 → 결과 표시(`source: ai` 배지) → 인기 검색어 상위 진입 시 검수 큐로

### 1-4. 상태 정의

**주문 상태**: `pending_payment → paid → preparing → shipped → delivered → confirmed` / 분기: `cancelled(결제 전·준비 전)`, `refund_requested → refunded`, `return_requested → returned`
- 주류 특성: 배송 시작 후 단순 변심 취소 불가(고지), 파손·오배송은 판매자 책임 교환·환불.

**예약 상태**: `requested → confirmed | declined` → `visited | no_show | cancelled_by_user | cancelled_by_store`
- 즉시확정 매장은 `requested`를 건너뛰고 `confirmed`.
- 예약금: `deposit_paid` 플래그, 노쇼 시 매장 정책에 따라 몰수/환불.

### 1-5. 비기능 요구
- 390px 모바일 퍼스트, 첫 화면 LCP < 2.5s (정적 번들 + 데이터 API 캐시)
- 모든 UI 한국어, 라이트·다크 지원, 브랜드 색 #22406B(술)·#E4572E(음식)
- 성인 대상 서비스 표기(만 19세 이상), 주류 경고문구 상시 노출(국민건강증진법)
- 접근성: 터치 타깃 44px, 명도 대비 4.5:1
