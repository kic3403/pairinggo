# 11. 페어링 데이터 수집·검수·발행 운영 가이드 (Phase 2.5)

작성 2026-09-10 · 도구 3종: 엑셀 가져오기 · 자동 수집 · 검수 화면. 흐름은 항상 **후보 큐 → 검수 → 승격 → 발행 → 앱 핫스왑**.

## 0. 원칙

- 페어링은 **근거가 붙은 주장**이다. 근거 없는 조합은 `pairing_candidates`에 머물고, 승인돼야 `pairings`+`pairing_evidence`가 된다.
- **승격 규칙**: `official`/`sommelier` 근거 1개 또는 근거 2개 이상 → 게시(`curated`). 그 외 → 보류(`pending`, 앱에 안 나감). 두 번째 근거가 승인되면 자동으로 `curated`.
- 출처 등급과 점수대: official 95~97 · sommelier 92~94 · media 88~91 · **blog 84~87** · user 84~87. 점수를 비우면 등급 기본값(96·93·89·85·85).
- 인용문은 **120자 이내**, 출처 URL 필수, 원문 통째 복제 금지(저작권). 같은 URL의 근거는 한 페어링에 한 번만(자동 차단).
- 인스타그램은 약관 때문에 수집하지 않는다. 네이버·유튜브는 공식 API만.
- 우선순위: ① 입점 예정 양조장 제품 ② 페어링 5개 미만인 술(대시보드) ③ "찾았는데 없던 검색어"(대시보드) ④ 인기 검색어.

## 1. 엑셀로 직접 넣기 (양조장 홈페이지·식당·소믈리에 지인)

1. `pnpm db:template` → `packages/db/templates/pairing-candidates.xlsx` (이미 생성돼 있음)
2. **후보** 시트에 한 줄 = 술 × 음식 × 근거 하나. 열: 술이름* · 음식이름* · 추천이유 · 출처명 · 출처URL · 인용문 · 추천자 · 출처등급(드롭다운) · 점수 · 메모
   - 술·음식 이름은 **술 목록 / 음식 목록** 시트의 이름(별칭 가능) 그대로 → 자동 매칭. 목록에 없으면 그대로 적으면 "확인 필요"로 들어가 검수 화면에서 지정
   - 소믈리에 지인 추천은 출처등급 `sommelier`, 추천자에 "이름 (직함)", 출처명에 "○○ 인터뷰/시음" 처럼
   - 양조장이 알려준 건 `official`, 추천자에 양조장명
3. `pnpm db:import 파일경로.xlsx` (CSV도 됨) → `성공 N · 확인 필요 N · 중복 N`, 확인 필요 목록은 `packages/db/import-report.md`
4. 검수 화면에서 승인

**양조장에 물어보는 폼 (권장)**: 입점 제안 메일에 "귀사 술에 가장 어울리는 안주 3가지와 한 줄 이유"를 붙이고 답을 그대로 엑셀 `official`로 넣는다.

## 2. 자동 수집 (네이버 블로그·카페·뉴스 + 유튜브)

```bash
pnpm db:collect --top 10                 # 인기 술 10종, 4개 소스
pnpm db:collect --drink d01,d38 --naver-news --youtube
pnpm db:collect --all --dry              # DB에 안 넣고 요약만
```
- 검색어: `"{술 별칭}" 안주` / `페어링` / `어울리는 음식` (따옴표 = 정확 구문, "서울의밤" 같은 일반 단어 대응)
- 추출: 제목+요약에서 **카탈로그 음식 이름·별칭이 등장**하면 후보 1건(AI 없음). 뉴스는 `media`, 나머지는 `blog`. 같은 (술, 음식, URL)은 중복 차단
- 결과 `packages/db/collect-report.md`. 후보에는 검색어·언급 수가 붙어 검수 화면에서 "언급 N" 배지로 보인다
- 한계: 이름만 스치는 글(주점 메뉴판, 산행기)도 잡힌다 → 검수에서 "관련 없음"으로 거절. 파일럿(금정산성·복순도가 44건 → 후보 31건)에서 절반 정도가 유효했다

## 3. 검수 화면 (`/admin`)

- 접속: `http://localhost:3000/admin` (배포 후엔 서버 주소/admin). 비밀번호는 `apps/web/.env.local`의 `ADMIN_PASSWORD` — **기본값을 바꿔서 쓰세요**. 폰에서도 됨
- **대시보드**: 대기·지정 필요·승격 수, 페어링 5개 미만인 술, 없던 검색어(수집 우선순위), 미발행 승격 수
- **검수**: 언급 많은 순 카드. 필터 상태·등급·술. 카드에 술×음식, 인용문·원문 링크·검색어, 기존 페어링 유무(있으면 근거만 추가; 같은 URL이면 "거절 권장")
  - **승인**: 등급·점수·추천자 확인, **추천 이유 필수**(앱 카드에 그대로 표시) → 승격 결과 토스트(게시/보류)
  - **거절**: 사유 선택(관련 없음·광고·근거 부족·중복·매칭 오류)
  - **술·음식 지정**: 매칭 안 된 후보(needs_entity)는 검색으로 골라 저장 → 대기로
  - 단축키 A 승인 · R 거절 · S 건너뛰기 · ↑↓
- **발행**: 미발행 승격 수 확인 → 발행 → `catalog_meta.version` 갱신 + 스냅샷 저장. 미니앱은 다음 시작 때 자동 갱신(재검수 불필요). 보류(pending)는 포함 안 됨
- 검수자 이름은 브라우저에 기억되며 근거의 추천자·후보의 reviewer로 남는다

## 4. 소믈리에 지인에게 부탁할 때

1. 검수 화면 주소와 비밀번호 전달 (전용 비밀번호를 쓰고 싶으면 Phase 4에서 계정 분리)
2. "카드마다 10초: 맞으면 A, 아니면 R. 이유는 한 줄이면 됩니다" — 승인 시 추천자 칸에 본인 이름·직함을 적으면 `sommelier` 근거가 된다
3. 한 시간에 200~300건 가능. 끝나면 운영자가 발행

## 6. 명령 요약

| 명령 | 용도 |
|---|---|
| `pnpm db:template` | 엑셀 템플릿 재생성 (술 목록은 시도별 묶음) |
| `pnpm --filter @pairinggo/db regional` | 전통주 지역별 목록 엑셀 재생성 (research/ 원본 기준) |
| `pnpm db:import <파일>` | 엑셀/CSV → 후보 큐 |
| `pnpm db:collect [--top N\|--drink ids\|--all] [소스 플래그] [--dry]` | 자동 수집 → 후보 큐 |
| `pnpm --filter @pairinggo/db pilot [--dry]` | `pilot/hits.json` 재적재 |
| `pnpm db:status` | 카탈로그·후보·로그 수, 마이그레이션, RLS |
| `pnpm db:export` | DB → `packages/shared/data/pairings.json` (번들 폴백 갱신, 커밋) |
