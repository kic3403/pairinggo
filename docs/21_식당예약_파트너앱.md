# 21. 식당 예약 + 페어링GO 파트너 앱 (1차 R1~R3, 2026-09-18)

술 검색 → 어울리는 음식 → 주변 식당 → **예약**까지 페어링GO 안에서 끝낸다. 식당 사장님은 별도의 **페어링GO 파트너** 웹앱(PWA)에서 예약·매장을 관리한다.

## 사용자 결정 (2026-09-18)
| 항목 | 결정 |
|---|---|
| 파트너 앱 | 별도 웹앱(PWA)으로 시작, 같은 저장소·같은 DB (`apps/partner`, Vercel 별도 프로젝트) |
| 파트너 가입 | 신청 → 운영자 승인 (`/admin/partners`) |
| 예약 확정 | **즉시 확정** — 사장님 수락 단계 없음. 매장이 정한 시간대별 정원 안에서만 받는다 |
| 매장 정보 수정 | 바로 반영 + 변경 이력(`merchant_changes`), 운영자가 되돌림 |
| 손님 번호 | 문자 인증(솔라피 — 알림톡과 같은 업체) |
| 알림 | 웹 푸시 + 카카오 알림톡 |
| 정산 | 시범 기간 수수료 명세만 (R5) |
| 리뷰 | 방문 완료 손님만 (R4) |

## 흐름
```
손님(페어링GO)                                   사장님(파트너 앱)
음식 상세 → 맛집 찾기 → [예약하기]                 가입 신청 → (운영자 승인) → 예약 설정·영업시간 → 예약 받기 켬
/reserve/[카카오id]?food=&drink=                  오늘: 시간순 카드 · 20초마다 새로고침 · 새 예약 푸시
 날짜 → 인원 → 시간(캐시 없는 API) → 로그인           착석(방문 2시간 전부터) → 완료
 → 문자 인증(한 번) → 이름·룸·술 지참·요청사항          노쇼(방문 15분 뒤부터) · 매장 취소(사유 필수 → 손님 알림)
 → 매장 제공 동의(예약마다) → 즉시 확정(예약번호)
/my/reservations: 방문 1시간 전까지 취소            예약 목록(다가오는·지난 30일) · 매장 정보 · 예약 설정
```

## 상태
`confirmed`(확정) → `seated`(착석) → `completed`(방문 완료) · `cancelled_by_user`(손님 취소) · `cancelled_by_store`(매장 취소) · `no_show`(노쇼).
정원 계산 = 확정 + 착석. 규칙은 `packages/shared/src/reservation/status.ts canTransition`, DB 함수 `reservation_transition()`이 같은 규칙을 한 번 더 확인한다(손님은 본인 예약만, 매장은 소속 파트너만).

## 개인정보·약관
- 개인정보처리방침: 예약 수집 항목, **매장 제3자 제공**(예약마다 동의, 방문 90일 뒤 매장 화면에서 번호 가림), 솔라피 위탁(도입 시), 웹 푸시 전달 경로, 예약 기록 1년·인증 기록 1일 보관. → `CONSENT_VERSION` 2026-09-18(기존 회원 재동의).
- 이용약관 제6조의2(식당 예약): 중개자 지위, 즉시 확정, 1시간 전 취소, 노쇼 제한, 5건·같은 날 1건.
- 탈퇴: 앞으로의 예약 취소(매장 알림) + 모든 예약의 이름·번호 삭제 + 알림 구독 삭제.
- 아침 크론이 보관 기한을 지킨다(예약 1년, 인증 1일, 발송 기록 180일).
- 퍼널 이벤트: `reserve_click`·`reserve_submit`·`reserve_confirmed`·`reserve_fail`·`reserve_cancel`(개인정보 없음).

## 알림
| 언제 | 누구에게 | 웹 푸시 | 알림톡 템플릿 환경변수 |
|---|---|---|---|
| 예약 확정 | 매장 | 새 예약 · 일시 · 이름·인원·요청 | `SOLAPI_TPL_STORE_NEW` |
| 예약 확정 | 손님 | 예약이 확정됐어요 | `SOLAPI_TPL_USER_CONFIRMED` |
| 손님 취소 | 매장 | 예약 취소 | `SOLAPI_TPL_STORE_CANCELLED` |
| 매장 취소 | 손님 | 매장에서 예약을 취소했어요 + 사유 | `SOLAPI_TPL_USER_CANCELLED` |
| 당일 아침 | 손님 / 매장 | 오늘 예약이 있어요 / 오늘 예약 N팀 | `SOLAPI_TPL_USER_REMINDER` / `SOLAPI_TPL_STORE_TODAY` |

알림톡 변수: `#{매장}` `#{일시}` `#{인원}` `#{예약번호}` `#{예약자}` `#{연락처}`(가림) `#{사유}` `#{매장번호}` (오늘 안내는 `#{팀}`). 심사용 문안 예시:
- 손님 확정: `[페어링GO] #{매장} 예약이 확정됐어요.\n일시: #{일시}\n인원: #{인원}\n예약번호: #{예약번호}\n방문 1시간 전까지 페어링GO 내 예약에서 취소할 수 있어요. 문의 #{매장번호}`
- 매장 새 예약: `[페어링GO 파트너] 새 예약이 들어왔어요.\n일시: #{일시}\n인원: #{인원}\n예약자: #{예약자}(#{연락처})\n예약번호: #{예약번호}`
- 손님 매장 취소: `[페어링GO] #{매장}에서 #{일시} 예약을 취소했어요.\n사유: #{사유}\n불편을 드려 죄송합니다.`

발송 결과는 `notifications`(sent·skipped·failed). 알림은 예약을 막지 않는다(저장 뒤 발송).

## 설정 전 동작
| 없는 것 | 개발 환경 | 운영 |
|---|---|---|

| 알림톡 채널·템플릿 | 로그만 | 건너뛰고 기록(skipped) |

## 사용자가 할 일
1. **Vercel 파트너 프로젝트**: 같은 GitHub 저장소로 새 프로젝트 → Root Directory `apps/partner`(설치·빌드는 `apps/partner/vercel.json`). 환경변수: `SUPABASE_URL` `SUPABASE_SERVICE_ROLE_KEY` `PARTNER_AUTH_SECRET`(새 무작위 32자+) `KAKAO_REST_KEY` `NEXT_PUBLIC_SITE_URL` `PARTNER_SITE_URL` `VAPID_*` `NEXT_PUBLIC_VAPID_PUBLIC_KEY`.
2. **페어링GO(Vercel web)** 환경변수 추가: `VAPID_*` `NEXT_PUBLIC_VAPID_PUBLIC_KEY`(로컬 `.env.local`과 같은 값) `PARTNER_SITE_URL`. 크론 `/api/cron/reservations`는 `vercel.json`에 들어 있다.
3. 사업자등록 → 솔라피 가입·발신번호 등록 → 카카오 비즈니스 채널 연결 → 위 템플릿 심사 → `SOLAPI_*` 입력. **이 전에는 운영에서 예약이 열리지 않는다**(문자 인증이 필요).
4. 시범 식당 1곳 섭외 → 파트너 가입 신청 → `/admin/partners`에서 사업자 상태 조회 후 승인.
