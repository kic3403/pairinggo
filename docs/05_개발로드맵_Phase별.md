# 05. 개발 로드맵 — Stage 0~4 · Phase 1~9

전제: 혼자 + Claude Code, 일정 유연. 기간은 **집중 시 기준**이며 각 Stage 끝은 "출시 가능한 상태"다.
개발 트랙과 병행 트랙(법무·영업·데이터)을 같이 적는다. 병행 트랙이 늦으면 개발이 끝나도 출시가 안 된다.

## 0. 전체 그림

```
Stage 0  준비            2주   사업자·콘솔·정산대행·토스페이 청약·세무 자문 / 모노레포 셋업
Stage 1  추천 미니앱     5~6주 Phase 1~3  → 앱인토스 검수 제출 (검수 1~3개월 동안 Stage 2 개발) ※ Phase 1에 검색·추천·홈·상세 개선 포함
Stage 2  전통주 구매     5주   Phase 4~6  → 양조장 10곳 입점, 결제 오픈
Stage 3  식당 예약       6주   Phase 7~8  → 거점 구 20곳, 예약 오픈
Stage 4  확장           지속   Phase 9    → 스마트오더·AI 폴백·리뷰 커뮤니티·광고·와인/위스키
```
총 약 4개월(17주)이면 "구매 + 예약이 되는 앱"이 된다. 검수·계약 대기는 겹쳐서 진행한다.

## Stage 1 — 추천 미니앱 (4주)

### Phase 1 · 미니앱 이식 + 검색·추천·홈·상세 개선 (1.5~2주) — 2026-09-09 범위 확정
토스 제출 전에 기존 기능을 끌어올려서 올린다. 서버·로그인·결제 없음, 데이터는 `pairings.json` 번들 내장.

**1-a. 뼈대 (2~3일)**
- pnpm workspaces + Turborepo. `apps/miniapp`(앱인토스 Vite 템플릿), `packages/shared·ui`. (`apps/web`·`packages/db`는 Phase 2에서)
- `granite.config.ts` 브랜드(#22406B/#E4572E, 아이콘 `pairinggo-icons.zip`), 탭바 5개, 라우트 셸(S01~S09).
- 기존 `lib/data.ts·rating.ts·prefs.ts`, 컴포넌트 12개 → 이식. 앱인토스 콘솔 앱 등록, 샌드박스 QR 실기기 확인.

**1-b. 검색 엔진 (3~4일)** — `packages/shared/search`
- 정규화(공백·기호 제거·소문자), 자모 분해 인덱스, 입력 중(조합 중 자모) 접두 매칭, 오타 허용(자모 편집거리 ≤ 2, 짧은 검색어는 1).
- 검색 필드 확장: 이름·별칭·종류(탁주=막걸리 동의어)·맛 태그·지역·양조장·수상. 결과 그룹: 술 / 음식 / 종류·지역·양조장(→ 목록 화면).
- 랭킹: 정확 일치 > 접두 > 부분 > 오타, 동률은 트렌드 점수·수상 가중.
- 상황 검색(규칙 파서): "매운 안주에 어울리는 술", "도수 낮은 달달한 막걸리", "선물용 증류주", "기름진 음식" → {대상: 술|음식, 프로필 조건(sweet≥4, abv≤10…), 종류, 태그} 로 변환 → 필터·정렬 결과 + 해석 문구("도수 10% 이하 · 단맛 4 이상 탁주"). 미해석 시 일반 검색 폴백.
- 결과 없음: 유사 이름 3개(편집거리) + 종류 제안 + 인기 검색어. `search_logs`는 로컬 큐에 적재(Phase 2에서 서버 전송).
- Vitest: 정규화·자모·오타·동의어·상황 파서 케이스 40개 이상.

**1-c. 추천 결과 (1~2일)**
- **종합 탭**(기본): `0.6×es정규화 + 0.25×log(blog)정규화 + 0.15×pf.s` 가중 합, 근거 등급 보너스, 동일 음식·종류 편중 시 순위 보정. 전문가·대중 탭 유지.
- 카드에 종합 점수 산출 근거 툴팁(세 요소 기여도).

**1-d. 홈 재구성 (1~2일)**
- 검색창 → 상황 검색 예시 칩("매운 안주에 어울리는 술") → 종류별 탐색(탁주·약주·청주·증류주·과실주·리큐르·허니와인) → 지역별 → 오늘의 페어링 → 대통령상 → 인기 검색어 → 최근 검색.
- 종류·지역 목록 화면(S02b) 신설: 정렬(인기·도수·수상), 필터(도수 구간·맛 태그).

**1-e. 술 상세 보강 (1~2일)**
- 맛 프로필 5축 시각화(레이더 또는 바), 유사 술 추천 정확도(프로필 거리 반영), 오프라인 구매처 지도(카카오 정적 지도 이미지 또는 Phase 3 SDK 전까지 주소·길찾기 링크), 온라인 판매 불가 주류 안내 명확화.

- **상태**: 2026-09-09 완료 — docs/08_Phase1_결과보고.md
- **검증**: 실기기 5탭·390px·다크, 검색 케이스표(오타·띄어쓰기·초성·동의어·상황 10개) 통과, 종합 탭 상위 5개 수동 검수 20개 검색어, `pnpm test` 통과, 번들 용량 앱인토스 제한 이내.

### Phase 2 · Supabase 스키마 + 시드 + 공개 API (4~5일)

### Phase 3 · 핵심 화면 + 토스 로그인 + 식당 찾기 + 검수 제출 (1.5~2주)

## Stage 2 — 전통주 구매 (5주)

### Phase 4 · 파트너 어드민(양조장) + 상품·재고 (1주)

- 주문서 고지(통신판매중개자·판매자 정보·청약철회·성인 확인 배송), 앱인토스 기능성 푸시(결제 완료·배송).

- 앱인토스 콘솔에 '쇼핑' 기능 추가·재검수, 프로모션 상한(10%) 엔진.
- **검증**: 실제 양조장 1~3곳과 클로즈드 베타 주문 10건, 정산 명세 오차 0, CS 24h 응답.

## Stage 3 — 식당 예약 (6주)

### Phase 7 · 식당 어드민 + 경량 예약(요청→승인) (2.5주)
- 식당 프로필·영업시간·휴무, 메뉴 ↔ foods, 취급 주류 ↔ drinks → "이 집의 페어링".
- `reservation_settings·capacity·blocks`, 가용 슬롯 계산 함수 + 동시성 테스트.
- S15·S16: 날짜·시간·인원 → 요청 → 알림톡(매장) → 어드민 승인/거절 → 푸시(소비자). 자동 승인 옵션.

### Phase 8 · 즉시확정·예약금·노쇼 정책 + 과금 (2주)

## Stage 4 — 확장 (지속)

### Phase 9 · 선택 순서 (트래픽·영업 상황에 따라)
1. **AI 폴백 검색** (3~4일): 정규화 → 캐시 → Claude Haiku(JSON 스키마) → `source: ai` 배지 → 검수 승격 큐. 레이트리밋·일 상한.
2. **바틀샵 스마트오더** (2주): 바틀샵 입점·픽업 재고·픽업 주문·QR 인도 확인. 온라인 판매 불가 7종 + 와인·위스키 카탈로그 시작.
3. **리뷰 커뮤니티·페어링 기록 피드** (2주): 나만의 페어링 노트, 피드·좋아요, 인기 사용자 페어링 검수 편입.
4. **광고·노출 상품** (1주): 앱인토스 광고 SDK, 양조장 추천 노출, 오늘의 페어링 지정.
5. **파트너 도구 고도화**: 택배사 API 송장 자동화, 예약 웨이팅, 매장 POS 연동 검토.
6. **독립 PWA 배포** (선택): 토스 밖 유입·SEO용. 결제는 토스페이먼츠 직접(미니앱과 어댑터 분리).
