## 이번 계획의 핵심 결정 (Q&A로 확정)

| 항목 | 결정 | 근거 |
|---|---|---|
| 구매 모델 | **1단계 전통주 직배송 중개 → 2단계 바틀샵 스마트오더(픽업)** | 온라인 직배송이 합법인 주류는 전통주뿐. 108종 데이터·양조장 76곳 직판 확인 자산 활용 |
| 주류 범위 | **전통주 먼저 → 와인·위스키는 스마트오더 단계에서 확장** | 데이터·근거·구매처가 전통주 기준으로 구축됨 |
| 예약 | **자체 예약 시스템 풀 구축** (경량 요청→승인 → 즉시확정·예약금) | 캐치테이블·네이버 예약 공개 API 부재 |
| 인력·일정 | 혼자 + Claude Code, 일정 유연 | 단계마다 "출시 가능한 상태"를 만드는 로드맵 |
| 플랫폼 | **토스 앱인토스 주력** (독립 웹은 파트너 어드민·랜딩만) | 토스 로그인·토스페이·본인인증·푸시·트래픽을 그대로 활용 |
| 아키텍처 | **프론트 Vite+React 정적 번들 + 백엔드 분리(Supabase + Next.js API/어드민)** | 앱인토스는 SSR 불가·CSR/SSG만 허용 |
| 제휴·사업자 | 현재 0 — 개발과 병행 | Stage 0 준비 트랙과 영업 트랙을 로드맵에 별도 편성 |
| 예약 과금 | **입점 무료 → 확정 예약 건당 수수료 → 구독제 전환** | 제휴 0곳 상태에서 진입 장벽 최소화 |
| 초기 거점 | 서울 특정 구 (마포·종로·강남 중 선정, 기준은 02 문서) | 예약 가능 매장을 한 지역에 밀도 있게 |
| 산출물 | 마크다운 문서 세트 (이 폴더) | Claude Code가 개발 시 직접 읽는 형태 |

## 이 문서 세트를 쓰는 법

1. 새 모노레포를 만들 때 이 `docs/` 폴더를 통째로 저장소 루트에 복사하고, `07_CLAUDE_md_초안.md`를 `CLAUDE.md`로 저장한다.
2. Claude Code에 `"docs/05 로드맵의 Phase N을 플랜 모드로 시작해줘"`처럼 Phase 단위로 지시한다.
3. 각 Phase 완료 시 05 문서의 검증 체크리스트를 통과해야 다음 Phase로 넘어간다.
4. 사업자·토스페이·양조장 계약 등 개발 외 트랙은 06 문서의 체크리스트로 진행 상황을 관리한다.
