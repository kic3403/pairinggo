# 22. 전통주 구매 — 중개(입점) 설계

2026-09-20 사용자 결정: **중개부터 시작한다.** 직접 판매(직매장 + 타사 전통주 매입)는 준비와 자금 부담이 커서 보류하고, 나중 선택지로만 남긴다(2026-09-15 결정의 순서를 바꿈).
판매자는 각 양조장, 배송·CS도 양조장. 페어링GO는 **통신판매중개자 + 주류 통신판매 수단제공자**다. docs/02 §4의 구조를 웹(앱인토스 아님) 기준으로 고쳐 실행 설계로 옮긴 문서.

## 1. 법 구조 — 지켜야 할 선

| 당사자 | 지위 | 책임 |
|---|---|---|
| 양조장 | **판매자** — 전통주 제조자, 관할 세무서장의 **주류 통신판매 승인** 보유 | 상품·가격·재고, 포장·배송, 청약철회·품질 분쟁, 현금영수증·세금계산서 |
| 페어링GO | 통신판매중개자 + 수단제공자 | 판매자 신원 고지(전자상거래법 §20), 성인 확인, 주문 전달, 분쟁 창구, 주류 광고 규정 |
| 소비자 | 만 19세 이상 | 성인 확인, 수령 시 신분 확인 |

**빨간 선 (어기면 양조장 면허가 위험하다 — 국세청 서면-2023-소비-4309)**
1. 주류를 **자기 책임으로 사거나 팔지 않는다** — 재고를 갖지 않고, 우리 이름으로 판매하지 않는다.
2. 양조장 **계정을 대신 운영하지 않는다**(아이디·비밀번호를 받아 대신 등록·판매하는 것).
3. "판매대행 후 정산금에서 수수료 차감"은 동업경영으로 해석될 여지가 있다 → 대금 흐름을 아래 2장처럼 짜고, 국세청에 서면으로 확인받는다.
4. 온라인 판매 불가 주류(`NON_TRAD` 7종 등 일반주류)는 **상품 등록 자체를 막는다**. 전통주만 판다.
5. 광고 문구·미성년 판매 금지·경고 문구는 지금 푸터 규칙 그대로 상품·주문 화면에도 붙인다.

## 2. 대금 흐름 — 세 가지 안

| 안 | 구조 | 장점 | 위험 |
|---|---|---|---|
| A 대표몰 | 우리가 전액 수령 → 월 2회 수수료 떼고 양조장 지급 | 구현 쉬움, 한 번 결제로 여러 양조장 | **대금을 자기 계좌로 받음 + 정산 차감** — 수단제공자 범위를 벗어날 소지가 가장 크다 |
| **B 서브몰 분할정산 (권장)** | 양조장이 PG에 하위 판매자로 등록, 결제 대금이 **양조장 앞으로 직접** 정산. 우리는 중개 수수료만 받는다 | 대금이 우리 계좌를 거치지 않는다. 한 번 결제로 여러 양조장 주문 가능 | 양조장마다 PG 하위몰 가입 필요(입점 장벽), PG의 마켓플레이스 상품 계약 필요 |
| C 판매자 결제창 | 결제만 양조장 자체 PG로 넘김 | 법적으로 가장 안전 | 장바구니 합산 불가, 결제 이탈 큼, 주문 상태 추적 어려움 |

**B로 간다.** 수수료는 두 가지로 받을 수 있는데, ① PG 분할정산으로 우리 몫을 분리 수취 ② 월별로 양조장에 세금계산서 발행해 별도 청구. ②가 "정산금 차감"이라는 인상을 주지 않아 더 안전하다. **①·② 중 무엇이 가능한지를 국세청 사전 질의와 PG 계약에서 함께 확인한다.**

## 3. 입점 조건과 계약

입점 신청은 **파트너 앱(apps/partner)에서 받는다** — 양조장 파트너(merchants.kind=brewery)가 이미 있고, 한증류소가 1호다.

필수 제출: 사업자등록증 · **주류 통신판매 승인서 사본** · 주류제조면허증 · 정산 계좌 · 출고지/반품지 주소 · CS 번호 · 택배사·배송비 정책.
승인서가 없으면 **입점 불가** — 지금처럼 공식몰 링크만 보여 준다.

계약서에 넣을 것: 판매자 지위와 책임(상품 정보·배송·CS·청약철회), 수수료율과 정산 주기, 품절·미발송 기준(영업일 2일 내 발송), 가격·재고 관리 의무, 개인정보 위탁(주문자 정보), 금지행위(허위 표시·미성년 판매), 해지.
**수수료 (2026-09-21 사용자 결정 — 안 A)**: **시범 3개월 0% → 이후 5%**. 결제 수수료(2~3%)는 판매자 부담을 기본으로 하되 계약에 명시.
계약서에 **조정 조항**을 넣는다 — "월 주문 N건 이상이 되면 8%로 조정할 수 있고, 30일 전에 알린다".
근거(2026년 실측): 네이버 스마트스토어 주문관리 1.0~3.85% + 판매 1.001~4.004% = **약 4.6~7.6%** · 쿠팡 4~10.9% · G마켓·11번가 7~13% · 전통주 전문몰 비공개.
PG 2~3%를 판매자가 내므로 **우리 5% = 양조장 체감 7.5%**로 네이버와 비슷하고, 8%면 10.5%로 네이버보다 비싸다. 입점 0곳·주문 0건에서 시작하므로 낮게 잡고 실적으로 올린다(docs/02의 8~10%는 이 결정으로 대체).
수수료가 **월 몇 만 원 단위**라 별도 청구는 수금 비용이 더 클 수 있다 → PG 분할정산 수취가 가능한지 국세청 질의로 확인하고, 안 되면 시범 기간에는 0%로 두고 받지 않는다.

## 4. 파는 것

- 카탈로그 518종 중 **입점 양조장의 전통주만**. 상품은 카탈로그 술(`drinks.id`)에 연결한다 — 술 상세 화면에서 바로 사게 하려면 연결이 필요하다.
- 한 술에 용량·구성이 여럿이면 상품을 나눈다(500ml / 750ml / 2병 세트).
- 냉장(생막걸리)은 **아이스박스·냉장 배송 가능한 양조장만** 등록할 수 있게 표시하고, 여름철 주의 문구를 상품 화면에 붙인다.
- **여름철 규칙(잠정, 첫 입점 계약 전 확정)**: 6~9월 생주는 아이스박스 필수 · **금·토 출고 금지**(주말에 물류센터에 묵으면 상한다) · 상품에 "냉장" 칩과 수령 즉시 냉장 보관 안내.
- 선물하기·정기구독·페어링 세트(술+안주)는 3단계.

## 4-1. 배송비·택배사 (2026-09-21 사용자 결정)

**양조장이 직접 정한다.** 플랫폼이 강제하는 배송비·택배사는 없고, 우리는 입력칸과 권장값만 준다.

### 배송비 (파트너 앱 `/seller` 배송 설정)
| 칸 | 뜻 | 비고 |
|---|---|---|
| 기본 배송비 | 주문 1건에 붙는 배송비 | **0원을 넣으면 "무료배송"**으로 보인다 |
| 무료 배송 기준 | 이 금액 이상이면 배송비 0 | 비우면 "무료 기준 없음". 권장 표시는 3만 원(강제 아님) |
| 도서산간 추가비 | 제주·도서 추가 | 비우면 0 |
| 출고 소요일 | 결제 뒤 며칠 안에 보내는지(영업일) | 주문 화면에 "보통 N일 안에 발송" |
| 냉장 배송 | 가능·불가 | 불가면 냉장 상품을 등록할 수 없다 |

- **묶음배송**: 같은 양조장 상품은 몇 개를 담아도 배송비 1회. 장바구니는 양조장별로 묶어 배송비를 **따로, 처음부터** 보여 준다(결제 직전에 배송비가 뛰지 않게).
- **상품 하나만 무료배송**으로 하고 싶으면 그 상품에 "무료배송" 표시(`products.ship_free`) — 그 상품이 담기면 그 양조장 배송비는 0.
- 무료 기준을 넘겼는지는 **그 양조장 상품 금액 합계**로 따진다(다른 양조장 금액과 합치지 않는다).

### 택배사
- 양조장이 **목록에서 고르거나, 없으면 직접 입력**한다(이름 직접 적기).
- 목록(`shared/shipping.ts` `COURIERS`): CJ대한통운 · 우체국택배 · 한진택배 · 롯데택배 · 로젠택배 · 경동택배 · 대신택배 · 일양로지스 · 천일택배 · 합동택배 · CU 편의점택배 · GS Postbox. 목록에 있는 곳은 **송장번호로 바로 배송 조회 링크**가 붙는다.
- **직접 입력**: 이름(20자, 링크 금지)만 받는다. 조회 링크는 붙지 않고 손님 화면에는 "○○택배 · 송장 1234567890 (조회는 택배사 홈페이지에서)"로 보인다. 같은 이름이 여러 양조장에서 반복되면 운영자가 목록에 추가한다.
- 기본 택배사는 배송 설정에서 정하고, 주문마다 다른 곳으로 보냈으면 **송장 입력할 때 바꿀 수 있다**(그 주문만).

## 6. 데이터 (마이그레이션 0032~)

| 표 | 주요 칼럼 |
|---|---|
| `sellers` | merchant_id(=양조장 파트너), 승인서 정보, 사업자 정보, 정산 계좌, 출고지·반품지, **배송비·무료 기준·도서산간 추가비·출고 소요일·냉장 가능**, **택배사(코드 또는 직접 입력 이름·조회 주소)**, 수수료율, 상태(심사·승인·정지) |
| `products` | seller_id, drink_id(카탈로그 연결), 이름, 용량, 도수, 가격, 정가, 재고, 1인 구매 상한, 냉장 여부, **이 상품만 무료배송(ship_free)**, 사진, 설명, 상태(판매중·품절·중지) |
| `carts` · `cart_items` | user_id, product_id, 수량 (서버 저장 — 기기 바뀌어도 유지) |
| `orders` | 주문번호, user_id, 결제(PG 거래키·금액·수단·상태), 수령인 이름·번호·주소, 성인 확인 기록, 동의 버전, 주문 시각 |
| `order_items` | order_id, seller_id, product_id, **이름·가격 스냅숏**, 수량, 상태, 취소 사유 |
| `shipments` | order_id + seller_id 단위, **택배사(코드 또는 직접 입력 이름)**·송장번호, 발송·배송완료 시각 |
| `settlements` | 월·판매자별 판매액·수수료·결제수수료·지급액, 상태 |
| `stock_logs` | 재고 변동 이력(주문·취소·수기 조정) |

주문자 개인정보는 **판매자에게 제공**된다(배송을 위해) → 개인정보처리방침에 제3자 제공 항목을 넣고 `CONSENT_VERSION`을 올린다. 주문마다 "판매자에게 제공" 동의를 받는다(예약과 같은 방식).

## 7. 주문 상태

```
결제완료 ─▶ 발주확인 ─▶ 발송(송장) ─▶ 배송완료 ─▶ 구매확정(7일 자동)
   │            │
   │            └─▶ 판매자 취소(품절·사유 필수) ─▶ 환불
   └─▶ 손님 취소(발송 전까지 즉시) ─▶ 환불
배송완료 ─▶ 반품 신청(7일) ─▶ 회수 ─▶ 환불(부분 가능)
```
- **청약철회 7일** — 단순 변심은 왕복 배송비 소비자 부담, 파손·오배송·변질은 판매자 부담.
- 영업일 2일 안에 발송하지 않으면 어드민 대시보드에 경고(docs/06 주문 모니터).
- 부분 취소는 판매자 단위로 처리한다(양조장 A는 발송, B는 품절 취소).

## 8. 성인 확인

1. 가입 때 이미 **생년월일·만 19세**를 받고 있다(shared/profile).
2. 주문 시 **본인확인기관 성인 인증**(PASS·카드 본인인증, NICE/KCB — PG가 함께 제공하는 모듈 사용)을 한 번 받고 12개월간 유효로 둔다.
3. 주문서·상품 화면에 "만 19세 미만 판매 금지", 수령 시 신분 확인 안내. 판매자에게는 **성인 확인 배송** 옵션 사용을 계약으로 권고.

## 9. 알림

예약에서 쓰는 `packages/server/notify`(웹 푸시 + 솔라피 알림톡)를 그대로 쓴다.
손님: 결제 완료 · 발송(송장) · 배송 완료 · 취소·환불. 판매자: 새 주문 · 손님 취소 · 미발송 독촉(아침 크론).

## 10. 정산·세금

- 월 2회(1일·16일) 마감 → 전월 판매·수수료 명세 생성 → 판매자 확인 → 지급(또는 PG 자동 정산).
- 우리는 **수수료에 대해 판매자에게 세금계산서**를 발행한다. 상품 대금의 현금영수증·세금계산서는 판매자가 소비자에게.
- 정산 명세에는 판매액·취소·반품·결제수수료·중개수수료·지급액을 판매자별로 보여 준다.

## 11. 개발 순서

| 단계 | 내용 | 비고 |
|---|---|---|
| 1 | `sellers`·`products` + 술 상세 구매 상자 + 장바구니 + 주문서 + **PG 결제** + 주문 내역·취소 + 어드민 주문 관리 | 판매자 1~3곳, 송장·정산은 수기로 시작 |
| 2 | 파트너 앱 상품·주문·송장 화면, 알림, 배송 조회, 정산 명세 자동화 | 입점 10곳 목표 |
| 3 | 리뷰(구매 인증), 재입고 알림, 페어링 세트·선물하기, `/shop` 기획전 | |

1단계는 PG 연동을 빼면 지금 있는 부품(회원·파트너·어드민·알림·카탈로그)으로 대부분 만들 수 있다. **PG 계약이 가장 긴 선행 작업**이므로 먼저 시작해 두고, 그동안 화면·DB를 만든다.

## 12-1. 판매를 열기 전 체크리스트 (2026-09-21 기준 남은 것)

1차 화면·서버는 만들어 두었고(결제 제외), 실제로 손님에게 열기 전에 이것들이 끝나야 한다.

| 할 일 | 왜 |
|---|---|
| **PG 연동** — `/api/orders`가 결제 성공을 확인한 뒤 주문을 만들도록 바꾸기 | 지금은 `SHOP_TEST_PAY=1` 일 때만 시험 주문이 만들어진다 |
| **성인 인증**(본인확인기관) 붙이기 | 주문 전 만 19세 확인 — 지금은 가입 때 받은 생년월일뿐 |
| **개인정보처리방침에 구매 항목 추가 + `CONSENT_VERSION` 올리기** | 주문 정보를 판매자에게 제공한다(제3자 제공). 주문마다 받는 동의는 이미 붙어 있다 |
| **이용약관에 구매·청약철회 조항** | 중개자 지위·취소·반품 기준 |
| 주문 알림(손님·판매자) | 예약과 같은 `packages/server/notify` 사용 |
| 한증류소 통신판매 승인 번호 입력 → 어드민에서 판매 열기 | 승인 없이는 팔 수 없다 |
