# 04. 기술 아키텍처 · DB 설계

## 1. 제약에서 출발하는 설계 원칙

| 제약 (앱인토스) | 설계 결정 |
|---|---|
| SSR 불가, 정적 번들 업로드 | 미니앱은 **Vite + React CSR**. 데이터는 전부 HTTPS API로 |
| 토스 로그인만 | 서버가 인가코드→토큰 교환 → 자체 세션(JWT) 발급. Supabase Auth는 파트너/운영 어드민용 |
| 실물 결제 토스페이만 | 토스페이 결제 승인·취소·웹훅 처리는 **서버**에서만 |
| 외부 링크 제한 | 구매·예약·CS 모두 앱 내 완결. 허용 예외(법적 고지·제휴기관 공식 페이지)만 외부 |
| HTTPS만 | API·이미지·지도 SDK 모두 HTTPS |
| 탭바·브랜드 규격 | `granite.config.ts`에 brand 정보, 탭바는 제공 형태 |

## 3. 스택 상세

| 영역 | 선택 | 비고 |
|---|---|---|
| 미니앱 | Vite 6 · React 18 · TypeScript · Tailwind v4 · TanStack Query · Zustand · 라우팅은 web-framework 파일 라우팅 규칙 | TDS(`@toss/tds-mobile`)는 탭바·CTA 등 규격 요소에만 선택 사용, 나머지는 자체 디자인 |
| 백엔드 | Next.js 16 Route Handlers (Node runtime), zod 검증 | 서버 로직 한곳. Supabase Edge Functions는 웹훅·크론 보조 |
| DB | Supabase Postgres, RLS, pg_trgm | 무료→Pro(월 $25) 전환은 Stage 2 결제 시점 |
| 인증 | 소비자: 토스 로그인 → 서버 세션 JWT(Bearer, 15분) + refresh(30일) / 파트너·운영: Supabase Auth 매직링크 + 역할 | 소비자 `users.toss_user_key` 매핑 |
| 성인인증 | 토스 인증 '본인 확인' → 생년월일·CI 수신 → 만 19세 판정 → `ci_hash`(SHA-256+salt) 저장, 원문 CI 미보관 | 재인증 주기 12개월 |
| 결제 | 토스페이 (앱인토스 전용 가맹점 키) + 정산대행(토스페이먼츠 등) | 결제 승인·취소·환불·웹훅은 서버. 멱등키 필수 |
| 지도·장소 | 카카오 로컬 REST(서버 프록시, 키 보호) + 카카오맵 JS SDK(미니앱) | Google Places는 별점 보강 옵션(유료), 기본 OFF |
| 알림 | 소비자: 앱인토스 기능성 푸시 / 파트너: 카카오 알림톡(솔라피 등) + 이메일 | 템플릿 사전 승인 필요 |
| AI | Claude API (Haiku) — 미등록 검색어 페어링 생성, 검색어 분류 | JSON 스키마 검증, 캐시, 일 500회 상한 |
| 이미지 | Supabase Storage + 변환 | 상품·매장 사진 |
| 배포 | 미니앱 `npx ait deploy` / web Vercel / DB 마이그레이션 CI | GitHub Actions |
| 관측 | Sentry(양쪽), 이벤트 테이블 + 주간 리포트 쿼리 | 앱인토스 콘솔 지표 병행 |
| 테스트 | Vitest(로직·API), Playwright(어드민 핵심 플로우) | 예약 슬롯·주문 상태 머신·정산 계산은 반드시 유닛 테스트 |

### 4-7. 인덱스·보안
- `drinks.name/alias`, `foods.name/alias`: pg_trgm GIN. `chosung` btree.
- RLS: 소비자 데이터는 서버(service role)만 접근. 파트너 어드민은 `merchant_members` 기반 RLS. 운영자는 `app_metadata.role=admin`.
- 개인정보 최소화: CI 원문 미보관, 배송지는 주문 완료 후 90일 뒤 마스킹 배치.

## 6. 인증·결제 시퀀스

**토스 로그인**
1. 미니앱 `appLogin()` → `authorizationCode`
2. `POST /auth/toss/exchange` → 서버가 토스 토큰 API로 교환 → 사용자 정보(동의 범위) → `users` upsert → 세션 JWT(15분) + refresh(30일) 반환
3. 이후 API는 `Authorization: Bearer`

**성인인증**
1. 구매·예약 진입 시 `adult_verified_at` 없거나 12개월 경과 → 토스 인증 본인확인 호출
2. 결과(이름·생년월일·CI)를 서버가 검증 → 만 19세 이상이면 `adult_verified_at`, `ci_hash` 저장. 미만이면 차단 화면

**토스페이 결제 (주문)**
1. `POST /orders` → 재고 홀드(10분), `pending_payment`, 금액 서버 계산
2. 미니앱 토스페이 SDK 결제 → 결제 키
3. `POST /orders/:id/pay` (멱등) → 서버가 토스페이 승인 API → `paid`, 재고 확정, 판매자 알림톡
4. 웹훅으로 상태 이중 확인. 실패 시 홀드 해제

## 7. 데이터 이식 계획
- `packages/db/seed/import-pairings.ts`: `pairings.json` → drinks/foods/pairings/pairing_evidence. `NON_TRAD` → `online_sellable=false`. `ev` → evidence 행. `src` → `source_tier`, status=curated (profile 등급 포함 — 검수 표시는 tier로 구분).
- 슬러그 생성, 초성 컬럼 계산, 트렌드 jsonb 그대로.
- 검증: 108/110/851 카운트, 술당 페어링 ≥5, url 200 응답률(기존 check-links 스크립트 이식).
