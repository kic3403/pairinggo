# 23. 주종 확장(전통주·위스키·사케·와인)과 공통 가격·용량 필터 (2026-09-24)

전통주 중심 카탈로그에 위스키·사케·와인 주종을 더하고, `/drinks`를 주종 탭 → 세부 종류 칩 → 필터 바로가기 → 목록 순서의 '술' 목록으로 바꿨다.
모든 주종(과 '전체' 탭)에 **같은 가격·용량 필터**가 붙고, 판정은 **판매 규격(한 병) 단위**로 한다. 기존 전통주 데이터·id·URL·회원·리뷰·저장·페어링은 그대로다.
사용자 결정(2026-09-24): 목록은 `/drinks` 확장(탭바·헤더 '전통주' → '술') · 데모 술은 운영 DB에 `is_demo`로 넣되 로컬에서만 보임 · 가격은 **배송비·쿠폰 제외 한 병 참고가격**.
첨부 참고 화면(데일리샷·캐치테이블·Vivino)은 이 작업에서 접근하지 못했고, 요구사항 본문과 기존 코드 기준으로 만들었다.

### 1-3. 분류 정의 — `packages/shared/src/catalog/kinds.ts`
- 표시명과 DB 식별자 분리: `drinks.category`는 세부 종류 식별자(전통주는 기존 값 그대로 — 탁주·약주·청주·증류주·과실주·리큐르·브랜디·허니와인 · 새 주종은 `Subtype.categories[0]`), URL은 `Subtype.id`(영문), 화면은 `label`. '전체'·'더보기'는 저장값이 아니다.
- 전통주: 막걸리·탁주 / 약주 / 청주 / 증류주 / 과실주 / 리큐르·기타(리큐르·브랜디·허니와인). 추가 필터 원료(attrs.ingredient)·단맛/산미/바디/탄산(맛 프로필)·숙성(attrs.aged). 국내 생산이라고 자동 전통주가 아니다(kind 열이 정한다). 전통주 과실주를 와인 탭에 함께 보이는 컬렉션은 넣지 않았다(필요하면 `kind` 그대로 두고 화면 컬렉션으로).
- 위스키: 싱글몰트/블렌디드 몰트/블렌디드/그레인(싱글그레인·블렌디드 그레인)/버번/라이/기타(싱글팟스틸·콘·기타 확인된 종류). **생산지는 별도 국가 필터**(스코틀랜드·아일랜드·미국·일본·캐나다·대만·인도·한국·기타) — '아이리시'·'재패니즈'·'캐나디안'은 검색 동의어로 국가 조건에 잇는다. attrs: sub_region·distillery·age(int, NAS는 `nas: true`)·peat·cask[]·finish·cask_strength·single_cask·independent_bottling·serve[]. 버번≠미국 전체, 뉴월드는 저장값 없음.
- 사케: 특정명칭 9개(category) + 제조 특징 `attrs.styles[]`(나마·나마초조·나마즈메·니고리·스파클링·겐슈·무로카·고슈·기모토·야마하이) — "준마이 긴조 + 나마 + 니고리". prefecture·rice·polish·temp[]. 첫 줄 4개 + 더보기. 일본식 소주 없음. 미확인은 `category ''`(화면 '미확인') — 후쓰슈로 넣지 않는다.
- 와인: category = 색상(레드·화이트·로제·오렌지) / attrs.sparkling·skin_contact·fortified·sweetness·style(natural·dessert·champagne·cava·prosecco·port·sherry)·natural_note·organic_note·grapes[]·producer·region·vintage(int, NV는 `nv: true`)·tannin. 빠른 탐색 스파클링·주정강화·디저트는 속성으로 판정(`Subtype.attr`) → 로제 스파클링은 로제와 스파클링 둘 다. 샴페인은 스타일이지 스파클링 동의어가 아니다. 내추럴은 유기농과 별개 필드.
- 공통 음식 필터 `FOOD_FILTERS`(고기구이·회·해산물·튀김·매운 음식·전·한식·치즈·디저트)는 음식 분류·태그·이름으로 묶고, 술은 **등록된 페어링(byDrink)** 으로 걸린다.
- 검색: 주종·세부 종류 동의어(위스키/whisky/whiskey, 준마이/쥰마이/junmai …)는 `kindSynonyms()` → `search/normalize.ts kindOfQuery`; 원어명·품종·스타일·증류소·생산자는 술 문서 별칭(`search/docs.ts`). 와인 낱말은 와인 데이터가 없는 동안 과실주로도 이어진다.

### 1-4. 필터 규칙 — `catalog/filter-url.ts`(순수, 클라이언트 공용)·`catalog/filter.ts`(엔진, 서버)
- `Range { min, max }` — `max: null` = **상한 없음**. 유한 상한(30만·50만)과 구분해 URL에서도 키를 뺀다(`pmin=200000`만).
- URL: `kind cat q pmin pmax vmin vmax amin amax food country flavor a.<속성> region brewery sort page`. 옛 링크 `?category=탁주`·`?region=`·`?brewery=` 그대로. 잘못된 값(음수·문자·범위 밖)은 무시.
- `matchSpec`: **같은 한 병 규격**에서 가격·용량 동시 충족. 조건이 켜졌는데 값이 없으면 불충족(0으로 보지 않음), 조건이 없으면 미확인도 보임. 세트(pack=set)는 기본 필터에서 제외.
- `filterDrinks`: 술마다 충족 규격 중 **최저 참고가격**을 카드 대표로, 결과 수 = 술 수. 같은 그룹 OR·그룹 간 AND. 주종 탭 수는 주종을 뺀 나머지 조건 기준.
- 정렬: 가나다(기본)·낮은/높은 가격순(대표 가격, 없는 술 마지막)·인기순(trend)·최신순(created_at). **평점순은 술 단위 평점 데이터가 없어 넣지 않았다.**
- `switchKind`: 가격·용량·도수·음식·검색어·정렬 유지, 세부 종류·주종 속성 해제, 국가는 새 주종 목록에 있는 값만, 지역·양조장은 전통주에서만.
- 슬라이더: 가격 0~1,000,000(2026-09-25 변경, 처음엔 300,000)·간격 1,000, 용량 0~3,000·간격 10 — 입력값이 넘으면 눈금 확장(`sliderMax`), 375처럼 간격 밖 값 유지. 빠른 가격 6개, 자주 쓰는 용량 13개(현재 결과에 있는 용량 먼저, 7개 + 더보기).

## 2. 화면
- `/drinks`(서버 렌더, URL이 상태): 검색창("술이나 음식을 검색해보세요") → 주종 탭 → 세부 칩(`SubtypeChips`, 단일 선택·더보기·자식 줄) → `FilterBar`([가격][용량][음식][전체 필터] 요약 버튼, 적용 칩 개별 ×, 결과 수, 정렬) → `DrinkCard`(사진/종류 타일·이름·주종·세부·생산지·"720mL · 참고가격 38,000원"/"정보 없음"·다른 용량 있음·음식 2·맛 2·하트) → 60개 페이지. 지역 칩은 전통주 탭에서만. 주종에 술이 없으면 "준비 중", 0건이면 완화 링크.

- `RangeSlider`: 겹친 range 입력 둘(키보드·44px 손잡이·구분 라벨) + 직접 입력(천 단위 쉼표) + 빠른 선택 동기화. 오른쪽 끝 = 상한 없음("1,000,000원 이상"은 눈금 끝).
- `/drinks/categories`: 왼쪽 주종 / 오른쪽 전체 보기 + 세부 종류(수), 같은 필터 상태 유지.
- 상세 `/drinks/[slug]`: 빵부스러기 홈›술›주종, 원어명, `SpecPicker`(규격 버튼 → 참고가격·유형·출처·확인일, `?spec=` 유지·공유), 구매(위스키·사케·와인은 온라인 구매 안내 대신 판매점 안내 — `onlineSellable`은 전통주만), 어울리는 음식(근거 페어링이 없으면 "페어링 정보 준비 중"), 맛과 향, `KindFacts`(주종별 정보), 회원 평가(기존), 비슷한 같은 주종 술.
- 검색: 주종·세부 종류 둘러보기 항목, 술 배지에 주종. 헤더·푸터·하단 탭바 '전통주' → '주류'(2026-09-25, 처음엔 '술'), 홈 바로가기 '술 전체'·'카테고리'. 페어링 카드에 음용 방식 배지.
- API `GET /api/v1/drinks/filter` — 목록과 같은 규칙, `count=1`은 수만, 아니면 60개씩.

## 3. 운영 입력
- **실데이터는 아직 없다**(위스키·사케·와인·가격·용량·사진). 데모 12종(`packages/db/research/additions/demo-kinds.json`, `--demo`)은 `is_demo`라 운영 화면에는 안 보인다. 실데이터가 들어오면 `delete from drinks where is_demo`.
- 넣는 길 세 가지: ① `add-drinks <json> --apply` — JSON에 `kind`·`country`·`attrs`·`nameOrig`·`aliases`·`specs[{ml, abv, vintage, pack, bottles, prices[{krw, type, source, url, checked}]}]` ② `specs-import <엑셀|CSV> --apply`(템플릿 `pnpm db:template` → '규격·가격' 시트: 술 id/이름·용량·도수·빈티지·병수·가격·유형·출처·URL·확인일) — 같은 규격의 옛 가격은 `valid=false`로 내리고 새 행 추가 ③ 어드민 `/admin/drinks/[id]` — 주종·세부·국가·원어명·별칭·속성·규격·가격, 저장하면 발행.
- 가격은 **그 규격 한 병의 확인된 값만**(권장소비자가 또는 판매처 가격, 출처·확인일 필수). 모르면 비운다 — 0원·0mL·추정값 금지. 세트는 pack=set+병수로 따로.
- 입점 상품(`products`, 판매가)은 참고가격과 섞지 않는다(상세 BuyBox 그대로).
- 페어링 점수는 기존 규칙 그대로. 친화도(`pairing/affinity.ts`)는 술 종류 × 음식 lift라 새 category는 근거가 쌓이기 전까지 중립(50) 근처에서 시작한다.

## 4-1. 테스트 이미지·외부 평점 (2026-09-25)
- 데모 12종에 가상 병 이미지(`apps/web/public/demo/d558.svg`~`d569.svg`, `image_credit` "데모(가상 이미지)")를 붙여 카드·상세의 사진 자리를 확인했다. 실제 제품 사진은 사용 허락을 받은 것만 `image_url`·`image_credit`에.
- **외부 평점**: `attrs.ext_rating = { source, score, scale, count?, url?, checked }`(`shared cleanExtRating`, 주종 공통 AttrDef type "rating") — 카드 이름 옆 "★ 4.2 출처", 상세 제목 아래 "4.2/5 (N명) · 출처 · 확인일 · 출처 보기", 어드민 편집 칸. 필터 조건으로는 쓰지 않는다.
