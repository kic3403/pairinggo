# 27. 전문가 등급(소믈리에) 페어링 검수 (2026-09-28)

> 화면 문구: 회원은 **"전문가 등급 요청"**(2026-09-28 사용자 요청 — "검수 신청"이 아님), 승인되면 "전문가 등급". 직함 보기의 소믈리에는 전통주·와인·사케·위스키로 나눔.

## 0. 결정 (사용자, 2026-09-28)
- 전문가는 **기존 회원 계정**으로 신청하고 운영자가 승인한다. 별도 어드민은 만들지 않는다(어드민 비밀번호는 하나뿐이라 외부에 열 수 없고, 근거에는 개인 이름이 붙어야 한다).
- 공개: **이름 + 소속**, 소속이 없으면 **이름 + 직함**("홍길동 소믈리에"). 이름은 실명이 기본이고, **실명 비공개를 고르면 신청 때 적은 닉네임**으로(2026-09-28 추가 결정). 직함은 **여러 개 + 직접 입력**(최대 4, "소믈리에·요리연구가"). 전문가가 신청 때 적고 운영자가 승인·표시명 편집.
- 동의 기준: 같은 조합에 "어울림" 전문가 **2명 이상 → 전문가 추천 · 5명 이상 → 전문가 적극 추천 · 10명 이상 → 전문가 Best 페어링**.
- 보상: 테스트 기간 없음. 출시 뒤 협찬·건당 사례 → 그때 카드에 "협찬"·"유료 자문" 표시(`experts.compensation`, 화면 표시는 아직 안 붙임).

## 1. 규칙 (`packages/shared/src/pairing/expert.ts`)
- 판정 `yes(어울림) · neutral(보통) · no(아님)`. **어울림 하나 = 소믈리에 등급 근거 한 줄**(무게 1.0 → 근거 확인). 보통·아님은 근거를 만들지 않고 세기만 한다. 아님은 한 줄 이유 필수.
- 근거 줄 `expertEvidence`: `source = "전문가 검수 · {표시명}"`, `who = 표시명`, `tier = sommelier`, `quote = 한 줄 이유`. source가 전문가마다 달라 `confidence.ts`가 각각 독립 출처로 센다(10명 = E 10).
- `applyExpertReview`: 이미 official·sommelier면 등급·점수·이유 그대로(근거만 보탬). 그 외는 sommelier로 올리고 점수 max(기존, 93).
- 배지 `expertBadge(xp)`: `어울림 ≥ 2 이고 어울림 ≥ 아님×2`일 때만. 단계는 어울림 수(2·5·10). 툴팁 `expertReviewSummary` "전문가 7명 어울림 · 1명 아님".
- 신청 `expertApplicationProblem`: 실명 2~20자 한글·영문(자격 확인용), 비공개면 닉네임 2~12자(운영자 사칭 금지), 직함 1개 이상·4개까지(`EXPERT_TITLES` + 직접 입력, `cleanTitles`), 링크 금지, 증빙 ≤3, 공개 동의 필수. 표시명 `expertDisplayName({realName, affiliation, titles, namePublic, penName})`.
- 하루 판정 100개(`EXPERT_REVIEWS_PER_DAY`).

## 2. 데이터 (0045)
- `experts`(user_id pk, status applied|approved|rejected|suspended, real_name, affiliation, title(표시용 "·" 연결), **titles text[]·name_public·pen_name(0046)**, display_name, intro, doc_paths, compensation, public_consent_at, applied_at, approved_at, reject_reason, reviews_count).
- `expert_reviews`(user_id, drink_id, food_id, verdict, note, pairing_id, evidence_id, created, prev, unique(user_id, drink_id, food_id)) — `partner_pairings`와 같은 구조.
- `pairings.expert_yes / expert_no` — 승인 전문가만 센 집계. `select("*")`·export로 번들 `Pairing.xp`.
- 증빙 사진: Storage **비공개** 버킷 `expert-docs/{userId}/`, 어드민만 10분짜리 서명 주소로 본다. 회원 API는 경로를 내보내지 않는다.

## 3. 서버 (`packages/server/src/expert-reviews.ts`)
- `saveExpertReview`: 이전 판정이 yes였으면 먼저 되돌림(근거 삭제 → 우리가 만든 행은 다른 근거가 0개일 때만 삭제, 아니면 prev 복원 — 현재 tier가 sommelier일 때만) → yes면 pairings 갱신/생성(sommelier 93, `checked_on` 오늘) + 근거 삽입 → upsert → `recountExpert` → `experts.reviews_count` → `catalog_meta.version`.
- `recountExpert`: expert_reviews와 experts는 서로 FK가 없어(둘 다 users를 가리킴) 조인 필터가 안 된다 → 두 번 읽어 승인 전문가만 센다. `recountExpertFor(userId)`는 승인·정지·재개 때.
- `removeAllExpertReviews`(탈퇴), `renameExpertEvidence`(표시명 변경 → 근거 줄 source·who).
- 대표 근거(`rows.ts pairingFromRow`)는 **출처 등급이 높은 것부터**(official → sommelier → media → blog → user) — 전문가 인용이 기존 블로그 인용에 가리지 않게(2026-09-28).

## 4. 화면
- 회원: `/expert/apply`(신청·상태), `/expert`(승인 전문가 — 검수 대기열·내 검수·새 페어링 제안), `/my` 전문가 줄, 헤더 "검수" 링크(`SavedProvider.expert`, `/api/account/consent`의 `expert`).
- 대기열 순서(`lib/experts.ts expertQueue`): ① 어울림 1명(배지 문턱 직전) ② 근거 확인인데 전문가 검수 없음 ③ 추정(맛 분석 점수순). 주종 칩, 30개씩.
- API `app/api/expert/{apply,reviews,queue}` — `requireExpert(req)`(같은 출처 + 로그인 + 승인).
- 어드민 `/admin/experts`(심사 중 먼저, 증빙 썸네일, 승인 때 표시명 편집, 반려·정지 사유, 표시명만 바꾸기) + 대시보드 "전문가 검수 신청 N건" + 활동 알림·웹 푸시(`expertPush`).
- 카드 배지 `ExpertBadge`(`.xbadge.rec/.strong/.best`) — 페어링 카드·오늘의 페어링·핫한 페어링.
